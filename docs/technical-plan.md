# 技术实现方案

## 范围与原则

本方案只实现 PRD V0.1 的研究闭环：讲述者提交真实素材，系统保留原始素材，AI 生成可审核的派生内容，讲述者得到并可修改记忆卡，管理员可修订每一步。任何支付、积分、社交、家庭圈、会员、数字人及公开分享均不在范围内。

## 架构

| 层 | 选择 | 原因 |
| --- | --- | --- |
| Web | Next.js App Router + TypeScript | 一套项目交付移动端 H5、服务端 API 和管理员界面。 |
| 数据 | Node 22 内置 SQLite；部署 PostgreSQL Adapter | 本地一条命令可启动；当前环境的 Prisma schema engine 无法创建 SQLite 文件，故不让 ORM 工具链阻断研究验证。 |
| 身份 | 邀请码 + scrypt PIN；管理员环境变量密码 | 符合种子测试流程；PIN 不保存明文。 |
| 会话 | HTTP-only、SameSite=Lax、签名 Cookie | 用户和管理员会话分离，前端不能读取凭据。 |
| 媒体 | 本地私有文件适配层；部署时切换 S3-compatible object storage | 开发文件不经公开 URL 暴露，读取必须经过 user_id 校验；部署改为短时签名 URL。 |
| AI | Provider Adapter | 转写、结构化提取、追问、作品生成不绑定单一供应商。 |
| 校验 | Zod + AI JSON Schema | 拒绝不合法输入；AI 输出失败时不会展示未经验证的故事。 |

## 数据边界

原始层只存用户提交的文本、原始音频、图片、视频及转写；派生层另存 MemoryUnit、追问、记忆卡与作品草稿。所有派生记录必须能追溯到 `response_id`。删除原始内容时，关联派生内容进入同一删除流程。每个业务查询必须带 `user_id` 过滤，管理员动作另写审计日志。

## 闭环处理

1. 用户提交素材，先持久化 Response 和私有 MediaAsset；任一步上传失败不删除已保存的原始输入。
2. 后台任务转写，失败也不影响原始素材保存。
3. 标准化文本输入 Provider Adapter，按严格 schema 提取 MemoryUnit。
4. 输出不合格时自动重试一次；仍失败时保存原始模型输出并标记管理员审核。
5. 独立的追问判断只生成零或一个问题；敏感、拒绝或连续短答直接停止。
6. 用户结束时仅依据已验证的 MemoryUnit 生成可编辑的 Memory Card。
7. 第 7 天作品仅选择经确认的 MemoryUnit，不补写用户没有表达的事实。

## 部署边界

本地使用 SQLite 与 `.env`，仅用于开发。共享测试环境切换为 PostgreSQL Adapter、HTTPS、私有对象存储和独立随机密钥。所有环境变量只在服务端读取；任何测试链接发布前均要替换本地管理员密码与会话密钥。
